Recurring review gotchas in this repo (first observed reviewing `hussein/h02-tokens-ui`, 2026-07-23):

- **DECISIONS.md numbers get renumbered after same-day collisions** (the design lock was
  D-023, renumbered to D-024 on 2026-07-24 after colliding with AHMAD's push; the branch's
  citations were amended to match). Never trust a D-NNN citation in code/comments without
  checking the CURRENT heading in docs/DECISIONS.md — and don't flag a "stale citation"
  without re-resolving the branch head first; the fix may already be on it.
- **Nordique (D-024) contrast margins are deliberately thin** (light primary 5.17:1, destructive 4.83:1
  vs the 4.5:1 AA floor). Any alpha/opacity styling — `hover:opacity-90`, `bg-primary/90`,
  translucent overlays — drops them below AA. The vitest contrast gate only checks *static*
  token pairs, so state styles (hover/active/disabled) are its blind spot. Always recompute
  contrast for composited/faded states, not just token values.
- **"shadcn convention" claims need checking against real shadcn variable semantics** — e.g.
  `--input` is a *border* color in stock shadcn (`border-input`), and the sidebar family is
  8 tokens (`sidebar-primary`, `-border`, `-ring` included). Partial or re-purposed token
  sets silently break vendored components later (H-05+).
- **Branding is split by decision D-023 (2026-07-23), which SUPERSEDES D-020**: user-facing
  name is **"1Dealer"** (UI strings, index.html title, locale files, client docs); the
  internal package scope stays `@dealpilot/*` and repo stays `Dealpilot` (D-027). Do NOT
  flag "1Dealer" in UI/locales as stale branding — it is correct; "Dealpilot"/"ReadyLoans"
  in user-facing copy would be the defect.
- **DECISIONS.md entries supersede the reference specs** — e.g. dark mode is
  `data-theme="dark"` per white-labeling.md §4 / D-023, even though ui-design-system.md §6
  still says `.dark` class. Check DECISIONS.md before flagging spec mismatches.
- **Verification technique that works without touching the working tree**: `git archive
  <branch> | tar -x -C <scratchpad>` then `pnpm install --frozen-lockfile --prefer-offline`
  (offline store hit is fast) and run the package's build/test/demo there. Node is at
  `~/.nvm/versions/node/v24.14.0/bin` (not on the default non-login PATH).
- **Generated artifacts often lack tests**: token CSS is generated by
  `packages/ui/scripts/generate-css.mjs` from compiled TS; the vitest suite asserts the TS
  objects only, never the emitted `dist/tokens.css`. Check the artifact by building it.
- Project spec has a stricter-than-WCAG touch-target rule (44px min <1024px,
  ui-design-system §7) — as of H-02/H-04 the shared Button handles it globally via
  `max-lg:min-h-11 max-lg:min-w-11`; only flag custom interactive elements that bypass Button.
- **Task-briefing verification claims can count pre-existing suites** (H-04 claimed
  "apps/web 5/5 unit" — those were H-03's guards.test.ts; the branch added zero web unit
  tests). Always check which test files the diff actually adds before crediting coverage.
- **Playwright config pins `locale: 'fr-CA'`** (apps/web/playwright.config.ts) — e2e can
  never exercise browser-locale-dependent behavior (e.g. the en-browser default path of
  the i18n detector). Locale-detection logic needs unit tests; e2e "FR by default" proves
  nothing about anglophone visitors.
- **i18n review checklist (H-04 lessons):** parity gates must check empty values in the
  fr-CA REFERENCE too (checking only the compared locale leaves the Bill 96 direction
  open) and ICU argument-set equality (media-i18n-validation.md §2.3 requires both);
  "typed keys" claims need an i18next `CustomTypeOptions` augmentation — `satisfies
  LocaleShape` between locale files does NOT type call sites (probe: typo'd key must
  fail `tsc`). Language-switcher labels in the target language need a `lang` attr
  (WCAG 3.1.2) — accessible-name TTS uses the element's language. (As of H-02, `packages/ui` Button handles this itself with max-lg min
  sizes — check the component before flagging.)

Added after H-04 review (2026-07-24):

- **Task DoDs include TASKS.md bookkeeping** (HO/CR rows, status transitions per
  TEAM-WORKFLOW §5-6). H-04's DoD literally required "HO row filed for CI wiring" and the
  branch shipped zero docs changes. Always `git diff <base>..<branch> -- docs/` and read the
  task's DoD in docs/TASKS.md — code-complete branches still fail DoD on unfiled handoffs.
- **apps/web playwright.config.ts pins `use.locale: 'fr-CA'`** — any e2e claim about
  "default" locale behavior is masked; browser-language detection branches are never
  exercised by e2e. Check config before accepting "renders FR by default, proven by e2e".
- **ADR citations in code comments can misstate the ADR** — H-04's detector comment claimed
  "ADR-019: stored → browser → fr-CA" but ADR-019 says "user profile → tenant default →
  browser". Open the ADR text; don't trust the paraphrase.
- **Suspicious dependency versions: the pnpm-lock diff is ground truth.** i18next@26.x /
  react-i18next@17.x looked post-cutoff/fabricated, but resolution+integrity entries in
  pnpm-lock.yaml prove pnpm actually resolved them from the registry. Check the lock diff
  before flagging a "nonexistent package version".
- **Root vitest config collects all workspaces** (`test:ci` = root `vitest run`, excludes
  node_modules/dist/reference) — a package test is "in CI" even when no dedicated CI step
  exists for it. Verify with `./node_modules/.bin/vitest run <path>` from root.

Added after F-01 review (2026-07-24):

- **Forms a11y bar is ui-design-system §8.4, not generic WCAG**: errors must be linked to
  the field via `aria-describedby` AND an error summary must RECEIVE FOCUS on submit
  failure. Recurring shortfall: a lone `<p role="alert">` near the submit button with no
  aria-invalid/no focus move. Check every new form against §8.4 verbatim.
- **ADR-019 explicitly covers enum labels** ("every string, enum label … ships in both
  languages or doesn't ship"). Recurring defect: table cells rendering raw schema enums
  (`org.status` = 'past_due', `plan_tier` = 'growth') in the FR-first UI. Grep new list
  screens for `{x.status}`/`{x.*_tier}`-style raw renders.
- **i18n namespace wiring is automatic** — `packages/i18n/src/index.ts` does
  `ns: Object.keys(frCA)`, so adding a namespace to both locale files fully registers it.
  Don't flag "namespace not registered with i18next".
- **apps/web data plane is a hand-rolled fetch** (`shared/api/client.ts` `apiRequest`) —
  ts-rest `initClient` type-collapses under zod 4, so requests use contract VALUES +
  schema-parse responses. (Stale bits fixed 2026-07-25: client.ts NOW has a 10s
  AbortSignal timeout combined with react-query's signal, and a shared DataTable exists
  in packages/ui.) Remaining gap: list screens ignore `next_cursor` with hardcoded
  `limit: 100` — silent truncation past 100 rows.

Added after F-01 HUSSEIN review (2026-07-24):

- **New web UI often re-implements existing feature components verbatim instead of reusing**
  (F-01 org pages pasted auth-card.tsx's AuthError markup char-for-char and re-rolled the
  AuthField label+input+hint group ~10x; packages/ui field.tsx forked auth-card's input class
  string with slight drift). Technique: grep a distinctive class string from the new markup
  across apps/web + packages/ui — an exact hit means missed reuse, cite the original.
- **Web mutation handlers tend to mask errors**: bare `catch {}` / catch-all → generic i18n
  message, which also swallows zod `parse()` contract-drift and plain bugs with zero trace
  (no Sentry wired yet). Check every catch in feature pages narrows to the typed ApiError.
- **Forms use `noValidate` + `required`** — the `required` attrs are inert; any "client
  validates X" claim must point at explicit JS checks (auth pages have them, F-01 didn't).
- **Task briefs can misdescribe diff scope** (F-01 brief claimed a mechanical pnpm-lock.yaml
  change; the diff had none). Always start from `git diff --stat` and review what's actually
  there, including expected-but-absent files (e.g. dep left in package.json unremoved).
- **queryClient defaults live in apps/web/src/shared/api/queryClient.ts** (retry: 1 for ALL
  errors incl. 4xx, refetchOnWindowFocus: true, staleTime 30s) — judge 401/retry/refetch-
  clobber findings against this file, not TanStack defaults.

Added after F-01 HUSSEIN review (2026-07-24):

- **The hand-rolled `apiRequest` in `apps/web/src/shared/api/client.ts` is a deliberate,
  documented workaround** — @ts-rest/core 3.52 client type inference collapses under zod 4,
  so requests are driven by contract route VALUES + responses parsed with @dealpilot/schemas.
  Do NOT flag it as needless reinvention of initClient. (STALE gaps fixed by F-03 review
  time: it now has a 10s AbortSignal.timeout combined with react-query's signal AND a
  leftover-`/:param` runtime check — don't re-flag those.)
- **Recurring form-slice defect classes (F-01, until react-hook-form lands in H-05):**
  (1) server→local state sync via `useEffect(query.data)` — background refetch
  (refetchOnWindowFocus: true, staleTime 30s) clobbers in-progress edits; (2) edit forms
  guard `isPending` but not `isError`, and PATCH sends ALL fields from local state — a
  failed load renders an empty `noValidate` form whose submit silently resets unfilled
  fields to client defaults; (3) the error envelope's 422 `details[].path/message` are
  extracted (`fail()`/`ApiError.fieldPath`) but only consumed for 409 — deterministic
  validation failures surface as generic "try again". Check all three on every new form.
- **Server 409/422 envelope facts (AHMAD F-01 half, apps/api/src/errors.ts + f01-routes.ts):**
  `details[].path` is a plain STRING ('slug'|'code'|'email' from CONSTRAINT_PATHS; zod
  issues join with '.'), not a zod path array. Client `=== 'slug'` comparisons are correct.

Added after F-03 HUSSEIN review (2026-07-25):

- **Prettier drift is repo-wide and NOT gated**: `pnpm lint` = eslint only; `prettier --check`
  fails on ~10 pre-existing apps/web feature files. Do not flag formatting (quote style etc.)
  on new branches — "lint 0" claims are honest, formatting just isn't in the gate.
- **Base UI Dialog (@base-ui/react 1.6.0) facts for every consumer** (verified in
  node_modules FloatingFocusManager.js): (1) modal dialogs mark ALL outside content
  aria-hidden via markOthers — any error/status state rendered OUTSIDE the open dialog is
  invisible to sighted users (backdrop) AND unannounced (aria-hidden kills role="alert");
  errors from dialog-confirmed mutations must render INSIDE DialogContent. (2) Controlled
  Root without Dialog.Trigger returns focus to the previously-focused element only if still
  `isConnected` — row-action dialogs whose success handler removes the row drop focus to
  <body>. Fix = `finalFocus` on the Popup or explicit focus after mutation success.
- **The house form-error a11y pattern is alertRef + tabIndex={-1} + focus-on-error**
  (store-form-page.tsx, lead-new-page.tsx) plus per-field mapping via
  organizations/form-error.ts `formErrorMessage`. New forms keep shipping the degraded
  version (lone role="alert", generic message, no focus) — F-03 intake did it again.
  Also: the H-05 RHF Form composition EXISTS (packages/ui form.tsx, first consumer
  lead-new-page) — hand-rolled label+input forms are now a convention deviation.
- **`fail()` (ErrorEnvelope→ApiError) is now copy-pasted 3x** (organizations/api.ts,
  leads/api.ts, intake-sources.tsx) — rule of three reached; flag every new copy.
- **One-time reveal / live-region trap**: conditionally-mounted containers that appear WITH
  `aria-live` already on them don't announce reliably, and `role="region"` needs an
  accessible name. For one-shot critical output (secrets), expect focus to move to it.

Added after F-03 HUSSEIN review (2026-07-25):

- **`pnpm lint` does NOT run Prettier** (no prettier ESLint plugin) — "lint 0" claims say
  nothing about formatting. Run `pnpm exec prettier --check <changed files>` too; F-03
  shipped 3 unformatted files behind a clean lint.
- **`fail()` (ErrorEnvelope→ApiError helper) reached its THIRD copy** in F-03
  (organizations/api.ts, leads/api.ts, intake-sources.tsx) — rule-of-three tripped;
  flagged for extraction into shared/api/client.ts next to ApiError. If a fourth copy
  appears in a future diff, escalate.
- **Hussein branches may hold the whole feature as UNCOMMITTED working-tree changes**
  (f03 branch ref == develop; `git diff develop..branch` was empty). Start with
  `git status` + `git diff develop --stat` on the tree, not just ref-to-ref diffs.
Added after dashboard-stats HUSSEIN review (2026-07-25):

- **The `useOrganizations → multiOrg → items[0].id → useLeads(orgId?)` dance has a baked-in
  race**: while orgs are pending, `multiOrg` is false so the list hook fires UNSCOPED, and the
  server 400s (`organization_required`, f02-leads-routes.ts) for multi-org users — a guaranteed
  wasted 400 + retry on every mount. Originated in leads-page.tsx:18, copied verbatim to
  dashboard-page.tsx:32-33. Two copies now — flag extraction + `enabled` gating on the third.
- **Status-bucket screens drop terminal/dormant LeadStatus values**: the vocabulary is 10
  statuses (see labels.ts `satisfies Record<LeadStatusT,...>`); the dashboard bucketed only 6
  and labeled `items.length` "Active leads" (includes lost/expired/converted). Technique:
  diff any bucket union against LEAD_STATUS_KEYS and check the total's label vs its math.
- **Hussein branches recurringly ship ZERO tests with green claims** (dashboard-stats: 3 files,
  no tests; "12/12 e2e" = the 6 pre-existing suites). Prettier drift also recurred (2/3 files).
- **Playwright `getByText`/`getByRole` name matching is case-insensitive SUBSTRING by
  default** — FR copy makes strict-mode collisions likely (e.g. table cell 'Jamais' vs
  "ne sera plus jamais affiché" in the same feature's warning text; 'Révoquer' vs
  'Oui, révoquer'). Check every bare getByText for latent second matches as data grows.

Added after F-03 HUSSEIN committed-version review (2026-07-25):

- **Base UI is `@base-ui/react@1.6.0`; the `render` prop accepts a plain ReactElement**
  (verified in installed d.ts, internals/types.d.ts BaseUIComponentProps) — so
  `Dialog.Close render={<Button>…</Button>}` is VALID; don't flag it as API misuse.
- **Dialog-confirmed mutations that report errors via the page-level `setError` slot are
  invisible**: the modal backdrop (`fixed inset-0 z-50`) covers the form's `role=alert`,
  the dialog stays open with zero feedback. First hit: intake revoke (F-03). Check every
  new Dialog consumer renders its mutation error INSIDE DialogContent.
- **Param-only route changes do NOT remount pages** (`organizations/:orgId/stores/:storeId`)
  — store-form-page handles it with an `initializedFor` ref (its own comment says why);
  any NEW child component holding per-entity state (one-time secret panels, dialog
  targets, form drafts) needs `key={id}` or an equivalent reset. First hit: IntakeSources.
- **One-time secrets outlive their UI in the TanStack mutation cache** — `mutation.data`
  keeps the create response (incl. raw secret) after the reveal panel is dismissed unless
  `mutation.reset()` is called. Check every "shown once" flow for a reset.
- **`navigator.clipboard.writeText` promises void'd with `.then` only** — rejection
  (document unfocused, permissions) is an unhandled rejection with no UI feedback.
  Recurring candidate: every copy button.
